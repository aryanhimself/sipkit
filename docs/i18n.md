# Internationalisation (i18n)

Roadmap item **V2-I18N-01**. Every user-visible string in `sipkit-ui` comes from a typed
message catalogue. English is the default and the source of truth. Nepali (नेपाली) is the second
built-in locale.

> **Review status: the Nepali strings need a native-speaker review before production.** They are
> a careful draft (telecom loanwords as agents say them, polite imperatives) and have not been
> reviewed by a native speaker yet. Corrections are welcome.

## TL;DR

| Want to… | Do |
|---|---|
| Show Nepali (React) | `<Softphone locale="ne" />` (or `ne-NP`, a list `['ne-NP', 'en']`, or `'auto'` for the browser languages) |
| Show Nepali (web component) | `<sipkit-phone locale="ne">`. The attribute is reactive |
| Rename one string | `messages={{ 'tab.contacts': 'Customers' }}` (React) or `element.messages = {…}` |
| Add a language at runtime | `registerLocale({ code: 'hi', messages: {…} })` (also `window.Sipkit.registerLocale`) |
| Translate in a custom component | `const t = useT(); t('controls.hold')` inside `<Softphone>` |
| Devanagari digits | `locale="ne-NP-u-nu-deva"` |

## How it works

| Piece | File | Notes |
|---|---|---|
| Catalogue (source of truth) | `packages/ui/src/i18n/en.ts` | Flat `'area.key': 'text'` object. `MessageKey` / `Messages` types derive from it |
| Nepali | `packages/ui/src/i18n/ne.ts` | Typed `Messages`, so a missing or extra key **fails typecheck** |
| Formatter | `i18n/format-message.ts` | ICU-lite: `{arg}`, `{n, plural, =0 {…} one {# …} other {# …}}`, `{x, select, a {…} other {…}}`. Plurals via `Intl.PluralRules`. No dependency |
| Registry + fallback | `i18n/locales.ts` | `registerLocale`, `resolveLocale`. Chain `ne-NP → ne → en`, so a partial locale shows English for missing keys |
| React | `i18n/context.tsx` | `I18nContext`, `useI18n()`, `useT()`. Outside `<Softphone>` the context is English |
| Number/date/duration | `lib/format.ts` | `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` (cached). Call timers, history dates ("Yesterday" / "हिजो"), volume %, quality numbers |
| Pseudo-locales | `i18n/pseudo.ts` | `createPseudoLocale()` → `en-XA` (accented). `{ rtl: true }` → `ar-XB` (accented, RTL). Not registered by default |

**Locale source, highest first:** the `locale` prop/attribute → the user's pick in Settings →
`config.language` → `'en'`. When the prop or `config.language` changes, the UI
switches live (no remount, calls keep running).

Bundle cost: the two catalogues plus formatter add roughly 8–10 KB gzipped to the IIFE (the
Nepali catalogue is about 4 KB of that). No i18n library is used.

### Core messages

Core stays language-neutral:

| Core output | UI mapping |
|---|---|
| `DisconnectReason` (`busy`, `no-answer`, …) | `endReason.<reason>` keys, via `i18n.endReason()` (typed map, so a new reason fails typecheck) |
| `SoftphoneError.code` | `error.<CODE>` keys, via `i18n.error(err)`. `ENGINE_ERROR` / `PLUGIN_ERROR` include the original message as `{detail}`. Non-core errors show their message |
| Registration failure (SIP code) | `sip.401`, `sip.403`, `sip.404`, `sip.408`, `sip.503`. Other codes show the server's reason |
| `notification` event | Core now adds an optional `code` + `params` (`missedCall`, `registrationFailed`, `conferenceMixingUnavailable`). The toaster translates `notification.<code>.title` / `.message`. Notifications without a code (plugins, host) are shown as sent |

## Adding a locale

1. Copy `ne.ts` to `<code>.ts`, type it `Messages`, translate every value. Keep the `{arguments}`
   and plural/select keywords unchanged; translate only the text.
2. Register it in `locales.ts` (`add({ code, messages, intlLocale? , dir? })`). Set `dir: 'rtl'` only
   if the language code is not already recognised (ar, he, fa, ur, … are detected).
3. Run `pnpm --filter sipkit-ui test`. `i18n.test.ts` checks: same keys as English, every
   message parses, same arguments as English, and (for Nepali) that values are actually translated.
4. Mark the review status in this file.

Hosts can do the same at runtime without a release: `registerLocale({ code: 'hi', messages })`.
Partial catalogues are fine (English fills the gaps).

## Key conventions

- `area.thing` in camelCase: `controls.hold`, `history.emptyTitle`, `settings.autoAnswerDescription`.
- Areas follow the screen or feature: `call`, `controls`, `transfer`, `incoming`, `dialpad`, `lines`,
  `login`, `history`, `contacts`, `conference`, `quality`, `settings`, `voicemail`, `dnd`,
  `registration`, `menu`, `theme`, `notification`, `error`, `endReason`, `sip`, `unit`.
- Mirrors of core enums use the core value verbatim: `endReason.no-answer`, `error.MAX_LINES`.
- One key per sentence. No string concatenation in components: put the whole sentence with
  `{arguments}` in the catalogue (word order differs between languages).
- Rich text: `i18n.rich('transfer.attendedSummary', { from: <b>…</b>, to: <b>…</b> })`.
- Plurals: always ICU `plural` with an `other` branch. Nepali has no grammatical plural for these
  nouns, so `ne` uses only `other`.
- `meta.languageName` is the language's own name, shown in the Settings language picker.

### Guard against new hard-coded strings

`packages/ui/src/i18n/no-hardcoded-strings.test.ts` parses `softphone.tsx`, `features/**` and
`components/ui/**` with the TypeScript compiler and fails on JSX text or string literals in
`aria-label`, `title`, `placeholder`, `alt`, `label`, `description`, `submitLabel` that contain
letters. Symbols and digits (`#`, `*`, `0`, `✓`, `—`) pass. A small allow-list covers example
values (`pbx.example.com`) and the brand monogram fallback.

## Nepali decisions

| Topic | Decision |
|---|---|
| Script | Devanagari. Technical terms that agents read in Latin stay Latin: SIP, WebSocket URL, MOS, ms, kbps, Esc, Enter, CRM |
| Wording | Loanwords as spoken in Nepali call centres: कल, होल्ड, म्यूट, अनम्यूट, ट्रान्सफर, कन्फरेन्स, भ्वाइसमेल, किप्याड. Polite imperative (-नुहोस्) for actions (कल काट्नुहोस्, उठाउनुहोस्); short nouns under the round in-call buttons (म्यूट, होल्ड) |
| DND | बाधा नदिनुहोस् |
| Digits | **Latin by default** (`ne` resolves to `ne-NP-u-nu-latn`). Phone numbers, extensions and the dialpad are always Latin because they are dialled, and timers/counts next to them read better in the same script. Hosts that want Devanagari digits for counts, timers and dates pass `ne-NP-u-nu-deva`; the dialpad stays Latin either way |
| Line badge | `L{line}` kept as is in Nepali (fits the narrow roster column). Reviewer to confirm |

## RTL

- The root sets `dir` and `lang` from the locale. Radix `Direction.Provider` makes menus, tabs and
  scroll areas follow it; the toaster gets `dir` too.
- Layout classes are logical: `ms-/me-`, `ps-/pe-`, `start-/end-`, `border-s/-e`, `text-start`.
  Do not add `ml-/mr-/pl-/pr-/left-/right-/text-left` to widget code.
- The keypad and the dial input keep `dir="ltr"` (1-2-3 order, numbers read left to right), and the
  SIP identity in the header is isolated with `<bdi dir="ltr">`.
- Smoke tests: `softphone-i18n.test.tsx` (pseudo RTL renders, keypad stays LTR) and
  `apps/playground/e2e/i18n.spec.ts` (switch to `ar-XB`, no horizontal overflow, key 1 left of 3).
  The playground has a Language switcher with an "RTL (pseudo)" option.
- Not done: phone numbers inside RTL sentences (history rows, call title) are not bidi-isolated, so
  `+977 980…` can reorder in a real RTL language. No RTL language is planned; fix with `<bdi>` when
  one is added.

## Not translated (on purpose)

- Developer-facing text: console logs, `embed.ts` status placeholders ("Waiting for a softphone
  factory…"), thrown error messages in core.
- Host-provided text: brand name, extension tab/action/panel labels, contact names, notifications
  without a `code`.
- `MockSoftphone` demo notifications (playground only).
